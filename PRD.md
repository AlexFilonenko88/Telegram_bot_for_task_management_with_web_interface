# PRD: Telegram-бот управления задачами с веб-интерфейсом

## 1. Обзор проекта

### 1.1 Цель проекта
Создать простой и эффективный инструмент для управления задачами через Telegram с возможностью просмотра статистики через веб-интерфейс. Система ориентирована на одного пользователя или небольшую команду до 5 человек.

### 1.2 Целевая аудитория
- Личные пользователи для управления личными задачами
- Малые команды (до 5 человек) для совместной работы над задачами

### 1.3 Ключевые преимущества
- Быстрое добавление задач через Telegram (без переключения контекста)
- Удобное управление задачами в мессенджере
- Визуализация прогресса через веб-интерфейс
- REST API для интеграций с другими сервисами
- Простой стек без сложной инфраструктуры

---

## 2. Функциональные требования

### 2.1 Telegram-бот

#### 2.1.1 Основные функции
- **Добавление задачи**: Пользователь отправляет текст — создается новая задача
- **Просмотр списка задач**: Команда для отображения всех задач с их статусами
- **Отметка выполненной**: Возможность пометить задачу как выполненную
- **Удаление задачи**: Возможность удалить задачу
- **Просмотр деталей**: Просмотр полной информации о конкретной задаче

#### 2.1.2 Команды бота
| Команда | Описание |
|---------|----------|
| `/start` | Приветствие и краткая справка |
| `/help` | Список доступных команд |
| `/add` | Добавить новую задачу через FSM (заголовок + описание) |
| `/list` | Показать список активных задач (без выполненных) |
| `/list all` | Показать список всех задач (включая выполненные) |
| `/done <id>` | Отметить задачу как выполненную |
| `/delete <id>` | Удалить задачу |
| `/stats` | Показать краткую статистику в Telegram |

#### 2.1.3 Работа с несколькими пользователями
- Каждый пользователь видит только свои задачи (для личного использования)
- Для командного режима: опциональное совместное пространство задач

### 2.2 Веб-интерфейс

#### 2.2.1 Основные функции
- **Просмотр всех задач**: Таблица с задачами и их статусами
- **Фильтрация**: Фильтрация по статусу (выполненные/невыполненные)
- **Статистика**: Графики и метрики выполнения задач
- **Редактирование**: Возможность редактировать задачи через веб (опционально)

#### 2.2.2 Статистика
- Общее количество задач
- Количество выполненных задач
- Количество невыполненных задач
- Процент выполнения
- График выполнения задач за неделю (по дням)

## 3. Пользовательские сценарии (User Stories)

### 3.1 Добавление задачи
**Как** пользователь  
**Я хочу** добавить задачу через интерактивный диалог  
**Чтобы** быстро зафиксировать задачу без переключения между приложениями

**Критерии приёмки:**
- Пользователь отправляет команду `/add` → бот запрашивает название
- Пользователь вводит название → бот запрашивает описание (или /skip для пропуска)
- После ввода описания задача создаётся
- Бот подтверждает создание и показывает название задачи
- Задача получает статус "активна"

### 3.2 Просмотр списка задач
**Как** пользователь  
**Я хочу** видеть список задач без выполненных  
**Чтобы** фокусироваться на актуальных задачах

**Критерии приёмки:**
- Команда `/list` показывает только активные задачи пользователя
- Отображается ID, текст и статус каждой задачи
- Список упорядочен по дате создания (новые сверху)
- Команда `/list all` показывает все задачи, включая выполненные

### 3.3 Отметка задачи выполненной
**Как** пользователь  
**Я хочу** отмечать задачи как выполненные  
**Чтобы** отслеживать прогресс

**Критерии приёмки:**
- Команда `/done <id>` меняет статус задачи на "выполнена"
- Бот подтверждает изменение
- Задача помечается с датой выполнения
- При попытке отметить несуществующую задачу — сообщение об ошибке

### 3.4 Удаление задачи
**Как** пользователь  
**Я хочу** удалять ненужные задачи  
**Чтобы** keeping список чистым

**Критерии приёмки:**
- Команда `/delete <id>` удаляет задачу
- Бот запрашивает подтверждение (опционально)
- После удаления задача исчезает из списка
- При попытке удалить несуществующую задачу — сообщение об ошибке

### 3.5 Просмотр статистики в веб-интерфейсе
**Как** пользователь  
**Я хочу** посмотреть прогресс за неделю на сайте  
**Чтобы** анализировать свою продуктивность

**Критерии приёмки:**
- Веб-страница загружается по адресу (например, `http://localhost:8000`)
- Отображаются ключевые метрики (всего/выполнено/невыполнено)
- Показывается процент выполнения
- График выполнения задач за неделю (по дням)
- Данные обновляются в реальном времени

### 3.6 Командная работа (опционально)
**Как** член небольшой команды  
**Я хочу** видеть задачи всех участников команды  
**Чтобы** координировать совместную работу

**Критерии приёмки:**
- Все участники команды видят общий список задач
- Задачи помечаются автором
- Возможность фильтрации по автору
- Конфликтные ситуации решаются (например, только автор может удалить свою задачу)

## 4. Архитектура

### 4.1 Ключевые принципы
- **Единственный источник правды — база данных.** Бот и веб читают данные через один и тот же API, а не напрямую из БД.
- **Бот — клиент API, не самостоятельный сервис.** Это позволяет переиспользовать логику и тестировать её через Swagger.
- **FastAPI — единственная точка входа в данные.** Вся бизнес-логика живёт здесь, не размазана по боту и веб-клиенту.

### 4.2 Компоненты системы
1. **FastAPI Backend** — REST API сервер с бизнес-логикой
2. **Telegram Bot (aiogram 3)** — клиент API, работает через polling
3. **Web Frontend** — клиент API для визуализации статистики
4. **Database** — SQLite (разработка) / PostgreSQL (продакшн)

### 4.3 Авторизация
- Авторизация по Telegram user_id
- Без регистрации и паролей
- Каждый пользователь видит только свои задачи

## 5. Нефункциональные требования

### 5.1 Производительность
- Время ответа бота на команду: < 1 секунда
- Время загрузки веб-страницы: < 2 секунды
- Поддержка до 5 одновременных пользователей

### 5.2 Надёжность
- Бот должен восстанавливаться после перезагрузки
- Данные сохраняются в SQLite и не теряются при перезапуске
- Обработка ошибок API Telegram

### 5.3 Безопасность
- Токен бота хранится в переменных окружения
- Валидация пользовательского ввода
- Авторизация по Telegram user_id (без паролей)

### 5.4 Usability
- Интуитивные команды
- Понятные сообщения об ошибках
- Поддержка русского языка

## 6. Технические ограничения и стек

### 6.1 Технологический стек
- **Backend**: FastAPI
- **ORM**: SQLAlchemy
- **База данных**: SQLite (разработка) / PostgreSQL (продакшн)
- **Telegram Bot**: aiogram 3.x
- **Frontend**: HTML + CSS + JavaScript (минимальный, без фреймворков)
- **Python версия**: 3.10+

### 6.2 Архитектурные ограничения
- Бот работает через polling (не webhook)
- SQLite в разработке, PostgreSQL в продакшн
- Один сервер для бота и веб-интерфейса
- Отсутствие системы авторизации (используется Telegram user_id)

### 6.3 Развертывание
- Локальный запуск или VPS
- Docker-контейнер (опционально)
- Использование systemd для автозапуска (опционально)

| Поле | Тип | Описание |
|------|-----|----------|

## 11. Риски и mitigations

| Риск | Вероятность | Влияние | Mitigation |
|------|-------------|---------|------------|
| Telegram API ограничения при polling | Средняя | Среднее | Соблюдать rate limits, при масштабировании — переход на webhook |
| SQLite блокировки при конкурентной записи | Низкая | Низкое | Для 5 пользователей достаточно, при масштабировании — миграция на PostgreSQL |
| Потеря данных при crash | Низкая | Высокое | Регулярные бэкапы SQLite файла |
| Долгий ответ бота | Средняя | Среднее | Асинхронная обработка с aiogram |
