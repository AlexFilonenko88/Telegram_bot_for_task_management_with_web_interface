# Минимальный production-мониторинг: чеклист (п.20)

Минимум для каждого production-сервера TaskBot. Статус — что уже в репозитории,
настроить — что делается руками на сервере/во внешнем сервисе.

| # | Пункт | Статус | Где |
|---|---|---|---|
| 1 | UptimeRobot на главный URL | настроить (внешний сервис) | шаг 1 ниже |
| 2 | Telegram-уведомления о падении | настроить (в UptimeRobot) + готово для бэкапов | шаг 2 ниже + `scripts/notify_telegram.sh` |
| 3 | Ежедневный автобэкап БД | **готово** | `scripts/backup.sh` (п.19): cron 3:00, хранение 7 дней |
| 4 | Копия бэкапов в облаке (3-2-1) | готово (включить `RCLONE_REMOTE`) | `scripts/BACKUP.md` → rclone |
| 5 | Grafana + Prometheus (опционально) | **готово** | п.17–18: `monitoring/`, Grafana :3000 |

Проверка всего чеклиста одной командой с ноутбука:

```bash
curl -fsS https://myapp.com/ >/dev/null && echo "API жив" || echo "API НЕ отвечает"
```

## Шаг 1. UptimeRobot на главный URL

Внешний мониторинг доступности — настраивается за 2 минуты, бесплатного
тарифа хватает. Внешний, а не скриптом на сервере, — принципиально: если
сервер лёг целиком, локальный монитор умирает вместе с ним и алерт не уйдёт.

1. Регистрация: https://uptimerobot.com (Free).
2. **Add New Monitor**:
   - Type: `HTTP(s)`;
   - URL: `https://myapp.com/` (главная отдаёт дашборд, код 200);
   - Monitoring Interval: `5 minutes` (минимум бесплатного тарифа — как раз
     порог «недоступен больше 5 минут» из чеклиста).
3. Сохранить — в течение минуты монитор станет `Up` (проверить на панели).

## Шаг 2. Telegram-уведомления о падении

1. **Отдельный бот для алертов** (не боевой TaskBot!): в Telegram у
   [@BotFather](https://t.me/BotFather) — `/newbot`, получить токен.
2. Написать новому боту любое сообщение (бот не может писать первым),
   затем открыть `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и взять
   `"chat":{"id":...}` — это `TELEGRAM_ALERT_CHAT_ID` (для личного чата
   положительное число).
3. В UptimeRobot: **My Settings → Alert Contacts → Add Alert Contact →
   Telegram** — вставить токен и chat id, подтвердить код в чате с ботом.
4. В мониторе (шаг 1) включить этот Alert Contact.

Проверка: в мониторе UptimeRobot «Pause» на 5+ минут — в Telegram должно
прийти уведомление о недоступности, затем о восстановлении.

### Алерты о сбоях бэкапа (уже в репозитории)

`scripts/notify_telegram.sh` шлёт сообщение через Bot API. `backup.sh`
вызывает его автоматически при сбое: добавь в `.env` сервера

```dotenv
TELEGRAM_ALERT_BOT_TOKEN=123456:ABC-...
TELEGRAM_ALERT_CHAT_ID=123456789
```

(переменные читаются из окружения/.env; не заданы — скрипт тихо пропускает
отправку и не ломает бэкап). Проверка вручную:

```bash
taskbot/scripts/notify_telegram.sh "тест алертов TaskBot"
```

## Шаг 3. Автобэкап БД — готово (п.19)

Убедиться на сервере: crontab содержит строку на 3:00, `ls -lh
/var/backups/postgres/` показывает свежие файлы не старше суток, в
`/var/log/backup.log` — `OK` и `Готово.` Подробно: `scripts/BACKUP.md`.

## Шаг 4. Копия бэкапов в облаке — правило 3-2-1

3 копии данных, 2 разных носителя, 1 вне офиса/сервера. У нас: живая БД (1) +
локальные бэкапы на сервере (2) + облако (3). Включается одной переменной в
cron-строке бэкапа: `RCLONE_REMOTE=remote:my-backups-bucket/postgres`
(настройка rclone — `scripts/BACKUP.md`, подходит Yandex Object Storage,
Backblaze B2, S3). Проверка: после ночного запуска `rclone ls` показывает
файл в бакете.

## Шаг 5. Grafana + Prometheus — готово (п.17–18, опционально)

Метрики CPU/RAM/диска предсказывают проблемы: `docker compose up -d` поднимает
Prometheus + node-exporter + Loki + Grafana (:3000). Дашборд Node Exporter
Full (ID 1860), PromQL-примеры — `monitoring/SETUP.md`.

## Итоговая проверка чеклиста

- [ ] UptimeRobot показывает Up, график без красных промежутков
- [ ] Тестовое уведомление Telegram получено (и от UptimeRobot, и от
      `notify_telegram.sh`)
- [ ] Ночной бэкап появился за сегодня и вчера, `backup.log` без ERROR
- [ ] `rclone ls remote:...` показывает сегодняшние бэкапы
- [ ] Grafana открывается, метрики сервера обновляются
